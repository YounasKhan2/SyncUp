## Call interpretation and exclusion rationale

- **AccountPanel:** sessions mount load and explicit refresh share GET; revoke awaits POST then reload; profile FormData conversion precedes PATCH; avatar File.arrayBuffer precedes PUT then GET then callback; delete uses its returned user. These are selected thin contracts, with sequencing retained in React. **SafetySettings:** block/unblock alters contact/request availability and has separate username reports; leave it unchanged rather than importing another feature's private report API.
- **Auth:** POST mode is sign-in/sign-up. Optional keyBundle inclusion depends on key generation; initialization and unlock retrieval are cryptographically ordered. No extraction.
- **Workspace:** paired inbox/request loads and direct/group call loads; timed incoming-call polling; queued ciphertext flush; accept/ignore then inbox refresh; sign-out then key lock; answer/accept/decline/end/leave orchestration. Even seemingly simple request accept/ignore belongs to existing orchestration in this slice.
- **Conversation:** metadata/message/call loads, encrypted-history paging, read sequence and typing, encrypted edits/submission, attachment intent/content/complete, reactions/deletion/pinning, group key lookup and call startup all stay with the current lifecycle. `encrypted` serializes the crypto result; outbox-specific serialization is shown explicitly in the table. **NewConversation:** discovery/contacts plus key retrieval and encrypted initial message/request/group creation stay unchanged. **ChatDetailsScreen:** discovery, membership, leave and conversion remain together. **SearchDialog:** existing debounce and AbortController remain. **ReportDialog:** only message report HTTP contract selected; its state and dismissal stay local. RequestsPanel itself has no direct transport; callbacks are owned by Workspace.
- **Calls:** `callApi` raw fetch forwards options/body, same-origin credentials and JSON headers; a 401 triggers its independent refresh POST, followed by at most one retry. It parses JSON as caller `T` and retains its call-specific error. The five invocations supply no body, including token acquisition and voice roster. No movement or refresh unification.
- **Media:** legacy metadata then downloadUrl fetch produces ciphertext ArrayBuffer; the hydrator decrypts/caches it. V2 metadata resolves `Metadata`, ranged downloads use Range plus signal and return ArrayBuffer records, with 200/206 interpretation and worker decryption unchanged. `uploadRange` uses `/api/uploads/v2/${job.attachmentId}/range`, exact staged Blob bytes and Content-Range, returns `{ acknowledgedBytes, complete }`, and interprets a resumable 409 specially. Finalize, intent creation, poster upload, session retrieval/deletion, staging and retry behavior remain frozen. Omitted apiUpload contentType in encrypted flows retains application/octet-stream.
- **Spaces:** metadata polling, permission editing, member/channel/category mutations, channel message/object refresh, encrypted legacy history, search, file lifecycle and shared-object state are authorization/lifecycle sensitive. `filePath` is `/api/spaces/${space.id}/channels/${activeChannel.id}/files/${intent.fileId}`; content PUT and complete POST precede file-list reload. `params` contains trimmed q plus optional from/after/before/has/objectType. The create-object `body: SharedObjectInput` is one of: poll `{ type, question, options, multiSelect, closesAt:null, anonymous }`; event `{ type, title, startsAt:ISO, endsAt:null, timezone, locationText, rsvpRequired:true }`; checklist `{ type, title, items:[{ text, assigneeId, dueAt:null }] }`. `response`/Updates `data` comes from SharedObjectCard unchanged: poll `{ type:'poll', optionIds }`, event `{ type:'event', rsvp }`, checklist `{ type:'checklist', itemId, done }`. State requests preserve `{ state }`. Updates fetch returns stacks/activeCalls and refreshes after response/state mutations. Inventory only; no extraction.
- **AppRouter/shared:** session bootstrap shares the `/api/auth/me` endpoint with Account but has a different ownership boundary. It does not import the private Account API. Shared transport remains the sole existing generic JSON/upload transport, with unchanged header, credential, error, refresh and retry handling.
